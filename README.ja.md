# MenuToggler

[English](README.md)

Unity Editorのメニューバーにあるメニュー項目を、個別またはグループ単位で非表示・再表示できるエディター拡張です。

## コンセプト

MenuTogglerは、Unity Editorのメニューバーを整理し、操作性を向上させるために開発されました。

ツールやパッケージを追加していくとメニュー項目が増え、頻繁に使用する機能を探しにくくなることがあります。

このツールでは、メニュー項目を個別または最上位のメニューグループ単位で非表示にできます。対象のツールやスクリプト、ファイルそのものを削除・変更することはありません。

非表示の設定はローカルに保存され、Unityがメニューを再構築した際にも自動的に再適用されます。

## 概要

- **Unityバージョン：** 2022.3.22f1
- **メニュー：** `nur_ieren > Menu Toggler`
- **設定保存先：** `UserSettings/nur_ieren/MenuToggler.asset`

## 機能

- **個別メニューの非表示** — メニュー項目を個別に非表示・再表示できます。
- **グループ単位の非表示** — `Tools` などの最上位メニューグループに属するすべての項目を一括で非表示・再表示できます。
- **メニュー検索** — 検索欄からメニューのパスを基準に項目を絞り込めます。
- **メニューの再読込** — 登録されているメニュー項目を再取得し、新しく追加されたメニューを一覧に反映できます。
- **すべて表示** — 非表示にしたすべてのメニュー項目を再表示し、保存された表示設定をリセットできます。
- **設定の永続化** — Unityの`ScriptableSingleton`を利用して、非表示にしたメニューのパスとグループをローカルに保存します。
- **非表示設定の自動再適用** — アセンブリのリロード、プロジェクトの変更、Edit Modeへの復帰後に設定を再適用します。
- **繰り返し再適用** — 一部のUnityイベント発生後、10秒間にわたって1秒間隔で非表示設定を再適用し、段階的に再構築されるメニューにも対応します。
- **保護されたメニューグループ** — `nur_ieren` メニューグループは一覧から除外され、非表示にできません。
- **ショートカット表記の正規化** — メニューのパスを表示・照合する際に、ショートカットキーの表記を取り除きます。

## 動作要件

- Unity 2022.3.22f1（本ツールの開発時の想定バージョン）

## 導入

`Assets/nur_ieren/MenuToggler/` フォルダをUnityプロジェクトにコピーしてください。

```text
Assets/
└─ nur_ieren/
   └─ MenuToggler/
      ├─ nur_ieren.MenuToggler.asmdef
      ├─ MenuToggleCore.cs
      ├─ MenuToggleSettings.cs
      └─ MenuToggleWindow.cs
```

`Assets/Editor/` に配置する必要はありません。付属のEditor専用asmdefによって、プレイヤービルドには含まれません。

## 使い方

1. Unityのメニューバーから `nur_ieren > Menu Toggler` を開きます。
2. 登録されているメニューグループの一覧を確認します。
3. 最上位メニューのチェックを外すと、そのグループに属するすべての項目が非表示になります。グループを展開すれば、個別の項目だけを非表示にすることもできます。
4. 検索欄を使用して、メニューの名前やパスから項目を絞り込みます。
5. 新しいスクリプトやツールを追加した場合は、`再読込` をクリックしてメニュー一覧を更新します。
6. `適用` をクリックして、表示設定を反映します。

   - 新しく非表示にした項目は、その場で取り除かれます。
   - 以前に非表示にした項目を再表示する場合は、Unityがメニュー構造を再構築できるようにスクリプトが再読込されます。

非表示にしたすべてのメニュー項目を再表示し、設定をリセットする場合は `全て表示` をクリックします。

`nur_ieren` メニューグループは一覧に表示されず、非表示にすることもできません。

## 仕組み

Unityには、登録されたメニュー項目を非表示にする公式の公開APIがありません。そのため、このツールではReflection（リフレクション）を利用して、Unity内部の `Menu.RemoveMenuItem` メソッドを呼び出しています。

`[MenuItem]` 属性によって登録されたメニューのパスを収集し、最上位のメニュー名ごとにグループ化したうえで、指定されたパスを現在のメニュー構造から取り除きます。

ただし、メニューの削除はメモリ上に存在するメニューに対してのみ有効です。ドメインリロードなどのエディターイベントが発生すると、Unityによってメニューが再構築されることがあります。

これに対応するため、保存された設定を以下のタイミングで自動的に再適用します。

- **Unity起動時：** 初期化後に保存されている非表示設定を適用します。
- **アセンブリのリロード後：** Unityによるアセンブリとメニューの再構築後に設定を再適用します。
- **プロジェクトの変更時：** アセットのインポートなど、プロジェクトに変更があった際に再適用を開始します。
- **Edit Modeへの復帰時：** Play Modeを終了してEdit Modeに戻った際に設定を再適用します。
- **繰り返し適用：** これらのイベント発生後、10秒間にわたって1秒間隔で非表示設定を再適用し、非同期または段階的に再構築されるメニューにも対応します。

設定は以下の場所に保存されます。

```text
UserSettings/nur_ieren/MenuToggler.asset
```

設定ファイルは `Assets/` の外に保存されるため、表示設定の保存によってアセットの再インポートが発生することはありません。

## 注意事項

- このツールが変更するのはUnity Editorのメニュー項目の表示状態のみです。対象となるツール、スクリプト、アセット自体を削除・変更することはありません。
- `[MenuItem]` 属性によって登録されたメニューのみが収集対象です。`File > New Scene` などのUnity内部のメニュー項目は対象外です。
- 検証用メニュー項目、`CONTEXT/` 形式のメニュー項目、内部メニューのパスは一覧から除外されます。
- `nur_ieren` メニューグループは保護されており、非表示にできません。
- Unity内部の `Menu.RemoveMenuItem` メソッドに依存しています。Unity内部の実装が変更された場合、他のUnityバージョンで動作しなくなる可能性があります。
- リロードやインポートの直後は、Unityがメニュー構造を再構築する間、一時的に非表示の項目が再表示されることがあります。
- ショートカットキーが設定されたメニュー項目は、ショートカット表記を除いたパスで表示されます。すべてのショートカット付きメニュー項目について、正常に非表示になることを確認できているわけではありません。
- 設定はローカルの `UserSettings/` に保存されます。他のプロジェクト利用者とメニューの表示設定を共有したくない場合は、このフォルダをバージョン管理の対象から除外することを検討してください。
